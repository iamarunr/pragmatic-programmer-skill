## What moved

- **Core behavior is at the ceiling in every condition.** On these tasks the skill does not change
  whether the code is correct.
- **v1 made no difference to the t1 misses.** Base and v1 both missed the README (0/2), the dashboard
  help text (0/2), and clock independence (0/2).
- **v2 moved exactly the targeted checks:** README 2/2, help text 1/2, clock independence 1/2.
- **v2 introduced one regression of its own:** a run's new regression test compares millisecond
  timestamps from the real clock and fails on a fast machine. The agent saw it pass once and reported
  success. v2's own warning ("tests that pass only because they run fast") did not prevent it.

## Cost

v2 runs took longer: about 1.5–2.5x base on t1 and t2. The t3 average includes one 225-second run,
most of it a browser check that hung. Another t3 run verified the UI in a browser but left the dev
server running. Both point at the same gap: verification steps that start processes need to finish
them, and should have a time budget.

## Caveats

Two runs per cell: one run flipping changes a cell by 50 percentage points. Treat this as direction,
not proof, and rerun with `REPS=3` or more through `run.sh` before relying on any single cell.
